# Forensic review of checkpoint 028's item-event stop

Date: 2026-09-10 UTC. Role: read-only engineering consultation in the shared workspace; this is not an independent scientific review. No native process, model request, authentication operation, or protected source modification occurred.

## Established from the report and unchanged controller

The supplied report is 385,483 bytes, SHA-256 `b96152d5f07f502a41b7e218417d20d6775b9751c7440f94de1015dc39cd336a`. Science executed 88 successful broker requests: 34 reads, 49 hashes, four page-image views, and one fixed observer audit. It then stopped with `Unadvertised native item effect`. The final notification was a correctly shaped `item/started`, bound to the accepted thread and turn. The session accepted 132 preceding item starts and 132 item completions. These facts establish that the broker-interface correction worked through substantial real interaction; they do not establish a scientific verdict.

The stop arises at the discriminant guard in `scripts/p3_reviewer_session_028.py` `_Events.item`, after checking that the item is a dictionary with a valid item identifier. Only `userMessage`, `agentMessage`, `reasoning`, `dynamicToolCall`, and `functionCallOutput` are admitted. The underlying item type is not copied to any report field. `last_notification_observation` retains the outer method and booleans only; `notifications` records accepted method counts, not individual type labels. `broker_boundary_failure` cannot diagnose this condition because it occurs outside the broker dispatch layer.

Thus the exact actual item type remains unknown. A missing/non-string type would also take this guard; if the item conforms to the pinned upstream protocol, it is one of the other 14 types below. One must not promote a plausible type into a recovered observation.

## Context compaction: source-supported hypothesis, not recovered fact

The pinned app-server explicitly suppresses deprecated `ContextCompacted` events because v2 receives the canonical `ContextCompaction` item. It forwards canonical ItemStarted/ItemCompleted events through the v2 item conversion. Therefore absence of `thread/compacted` in this report does not refute compaction. [bespoke_event_handling.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server/src/bespoke_event_handling.rs), accessed 2026-09-10, especially source lines 942–946 and 1022–1077.

All three inspected compaction implementations emit `TurnItem::ContextCompaction` through `emit_turn_item_started` before performing their compaction work: [compact.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/compact.rs), [compact_remote.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/compact_remote.rs), and [compact_remote_v2.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/compact_remote_v2.rs), all accessed 2026-09-10. Upstream tests explicitly expect started and completed context-compaction items: [compaction.rs tests](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server/tests/suite/v2/compaction.rs), accessed 2026-09-10.

The actual report gives no token totals or context-threshold measurement from which to prove automatic compaction. Its 89 token-usage notification count, 88 broker successes, and elapsed duration are not such measurements. The guard is also deliberately conservative: the source comment explicitly includes compaction among terminal effects. Accepting compaction would therefore be a change to the review control policy, not merely adding a harmless unknown string. No such amendment or native retry is proposed by this forensic work.

## Can the stopped item type be recovered from existing files?

There is no source-supported exact-type recovery route in the standard retained artifacts inspected here. No additional human log probe is justified solely to rediscover the same missing field.

1. The Python session does not save or hash raw stdout/stderr and clears all input/output/early-frame buffers during finalization. The report and separate SESSION file contain the same filtered observation, so uploading the separate SESSION file would not recover the lost type.
2. Native ordinary thread/rollout persistence is disabled by the ephemeral thread: `thread_persistence_fut` returns `None`, and the live thread's state database is also disabled. Core rollout-item persistence writes only through `live_thread`. [session/session.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/session/session.rs), source lines 816–918, and [session/mod.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/session/mod.rs), source lines 3910–3916; accessed 2026-09-10.
3. The separate rollout-trace bundle requires `CODEX_ROLLOUT_TRACE_ROOT`; the restricted environment does not pass it. [rollout-trace/thread.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/rollout-trace/src/thread.rs), source lines 101–115, accessed 2026-09-10.
4. `RUST_LOG=off` disables the ordinary stderr tracing layer. This does **not** disable the app-server's separate SQLite log sink: app-server attaches `log_db::default_filter`, whose default is TRACE. It would be wrong to infer that all native logs are absent. [app-server/lib.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server/src/lib.rs), source lines 605–680, and [state/log_db.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/state/src/log_db.rs), source lines 52–82, accessed 2026-09-10.
5. That log database is located at the run's `science_native/runtime_state/logs_2.sqlite`, with a `logs.feedback_log_body` column. However, outgoing notification logging uses `app-server event: {notification}` where `ServerNotification`'s strum Display produces **the outer wire method alone**, e.g. `item/started`, not the item payload/type. The actual stdio JSON serializer sends the complete payload only to stdout and has no raw-message logging. [state/sqlite.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/state/src/sqlite.rs), [outgoing_message.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server/src/outgoing_message.rs), [protocol/common.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server-protocol/src/protocol/common.rs), [transport/mod.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server-transport/src/transport/mod.rs), and [transport/stdio.rs](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server-transport/src/transport/stdio.rs), accessed 2026-09-10.

An unrelated native diagnostic or compaction span might establish that a compaction operation was considered or began. That would not establish that its item was the particular rejected frame, especially given queueing, buffering, log dropping and asynchronous process termination. The source does not support an SQL extraction of the exact discarded item type from the standard outgoing-notification log. No existing native database was opened and no raw model/credential/paper content was examined for this investigation.

## Engineering conclusion

The remaining demonstrated defect is lossy event diagnostics plus an event policy that necessarily stops on some valid source-defined lifecycle activity. The previous round corrected broker arguments and broker diagnostics; it did not cover the distinct item-event layer. A full event-policy audit should have accompanied the earlier whole-interface claim. This is not evidence that the user ran the command incorrectly, and it is not evidence that a selected scientific mechanism failed.

Do not propose a new native run solely on the unproven assertion that adding `contextCompaction` will solve the latest stop. Preserve the current run and its audit output; report the scientific verdict as absent. A future implementation, if the PI chooses one, must retain a bounded source-enumerated item type and validation-layer reason before rejection, while withholding unknown strings, text bodies, and arguments. The choice between admitting controlled compaction, bounding evidence/context consumption, or changing the review route is a scientific/operational design decision that this report does not silently make.
