# Native model catalog consultation

Engineering consultation only; this is not the independent scientific review. Access date: 2026-09-09. Native source audited at commit `78c290807ce710180111df227df3b7a4fe845452` (Codex 0.151.0). No native process, account action, credential read or model turn was performed for this consultation.

## Finding and recommendation

REPORT(10) reaches model selection after configuration, requirements, account and rate-limit admission. Its complete returned catalog has seven entries, including hidden entries, and lacks the exact requested identifier `gpt-6-astra`. The current exact-model gate correctly stops before thread creation or a model turn. The missing verdict is expected.

There is no supported force-refresh parameter on this version's `model/list` RPC. I found no deterministic correction within the unchanged RPC, executable and read-only host-cache contract that would force Astra to appear or attest a fresh remote catalog. Do not change client/cache/configuration, invent an RPC parameter, make a blind Astra model request or silently choose another model to get past this gate. Another identical launch would be an unverified retry rather than a demonstrated repair. A different reviewer model requires an explicit amendment to the exact-model scope; this consultation does not authorize or execute it.

## Exact source findings

1. `ModelListParams` contains only `cursor`, `limit` and `includeHidden`. `CatalogRequestProcessor::list_models` forwards the hidden flag and paginates the catalog; `supported_models` uses `RefreshStrategy::OnlineIfUncached`. There is no `refreshCache` or provider-selection request field. [Catalog processor](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server/src/request_processors/catalog_processor.rs), [supported_models](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server/src/models.rs), [request schema](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server-protocol/schema/json/v2/ModelListParams.json). Accessed 2026-09-09.

2. Discovery does not filter by `multi_agent_v2`, `code_mode_host`, environment capabilities, model specialty or the reviewer restriction profile. The manager sorts priority and applies only the authentication predicate `chatgpt_mode || supported_in_api`; the app-server then filters picker visibility unless `includeHidden` is true. The receipt requested hidden entries. Therefore those disabled reviewer features are not a source-supported explanation of Astra's absence. This says nothing about whether Astra would pass later runtime checks if advertised. [Manager](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/models-manager/src/manager.rs), [model preset conversion and filtering](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/protocol/src/openai_models.rs). Accessed 2026-09-09.

3. The cache TTL is 300 seconds; eligibility uses the JSON entry's `fetched_at` and client version, not filesystem modification time. A cache miss, invalid entry or read failure leads to an online attempt for authenticated Codex-backend discovery. A failed remote refresh is logged, while `raw_model_catalog` still returns the current in-memory catalog. Thus RPC success and complete pagination do not establish a successful current network refresh. [Cache](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/models-manager/src/cache.rs), [manager](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/models-manager/src/manager.rs). Accessed 2026-09-09.

4. On a successful remote response, `fetch_and_update_models` applies the models and ETag in memory **before** attempting `cache.store`. A cache-write failure is logged and discovery returns success. The read-only cache mount therefore does not by itself discard fresh remote metadata or justify making that mount writable. No actual cache-write outcome is inferred from REPORT(10). [Manager](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/models-manager/src/manager.rs). Accessed 2026-09-09.

5. App-server construction starts a background worker which attempts online discovery immediately and subsequently every 270 seconds. It offers no RPC completion/freshness attestation in the model response. Waiting for a nominal interval or calling `model/list` again would not prove a remote success. [Worker](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server/src/models_refresh_worker.rs), [startup](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/app-server/src/message_processor.rs). Therefore the receipt is not the unchanged bundled catalog. It remains compatible with a cached catalog or a remote result; those alternatives are not distinguished by the safe receipt. ## Limits

Astra's absence from this one returned catalog is not evidence that the user's subscription lacks Astra, that Astra cannot be used through any Codex route, or that the model is unsupported globally. Current OpenAI documentation is product-level information and does not attest this account's native catalog or entitlement. The supported-effort list for another advertised model likewise does not establish an actual successful model turn, the formal reviewer boundary or scientific competence. The original requested model and all frozen scientific material remain unchanged.

## Effort addendum for a possible explicit scope amendment

The exact native client translates a locally selected Ultra effort into the catalog’s valid non-Ultra multi-agent effort if present, otherwise Max when supported, otherwise the last supported non-Ultra effort, and finally Medium. In the separate multi-agent policy function, Ultra selects Proactive only when the effective runtime is V2 and no custom mode hint overrides the built-in policy. A non-V2 runtime returns no such mode. This source does **not** show that Ultra would launch subagents through the current disabled-V2 review profile. It does show that Ultra is not an additional backend reasoning level above Max. If the PI proposes a single-agent reviewer exception, explicit Max is a coherent declared setting when the live catalog advertises it; selecting it must be covered by the amended model-and-effort scope, with no silent fallback.
