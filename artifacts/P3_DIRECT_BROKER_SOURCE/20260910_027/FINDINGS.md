# 026 Code Mode failure: source audit and minimal repair

Date: 2026-09-10. Engineering audit by a shared-workspace subagent; **not an independent scientific review**. No Codex native process, credential operation or model turn was run. Twenty official source blobs were fetched at commit `78c290807ce710180111df227df3b7a4fe845452`, verified against their Git blob identities, and recorded in `MANIFEST.json`. Existing pinned source supplies configuration and first-turn warning code.

## Decision

**Keep the current disabled Code Mode host and direct broker tools. Do not install or enable a new execution host as the first repair.** The captured warning concerns an unavailable Code Mode executor. It does not prove that the separately exposed direct broker functions are unavailable. The existing profile deliberately marks the `functions` namespace as direct only; pinned upstream code and an explicit upstream test support exactly this configuration under CodeModeOnly.

The concrete repair is narrowly scoped notice handling, followed by the already-required real direct broker canary and refused read before opening a fresh scientific reviewer. It requires a finite budget amendment because the current 6-start/3-turn ceiling is exhausted. It does **not** require additional host access, changed model metadata, a weaker reasoning effort, more filesystem mounts, or a new sign-in.

## Established report facts versus source-derived inference

The attached 026 report records the complete-template family `tools.code_mode_unavailable`, behavior `fail_closed`, and exact active-thread binding. It deliberately omits the internal reason. It also records no scientific start and no verdict. The parent separately verified report/source pins and the published checkpoint. This audit does not retroactively identify the discarded warning from 024.

The observed profile has `features.code_mode_host = false`, `features.code_mode_only = false`, and `features.code_mode = { enabled = false, direct_only_tool_namespaces = ["functions"] }`. At the pinned source, a literal host boolean supplies no host subconfiguration, so `disable_in_process_fallback` defaults to false. ThreadManager therefore chooses DisabledCodeModeSessionProvider, whose availability method returns a fixed disabled-host error. These are **source-derived consequences of the verified configuration**, not separately measured internal runtime fields. [Configuration resolution](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/config/mod.rs#L2650-L2677), [provider selection](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/thread_manager.rs#L461-L468), [disabled provider](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/code-mode/src/remote_session.rs#L92-L111). Accessed 2026-09-10.

Model metadata `tool_mode` takes priority over the two feature switches. With unavailable Code Mode and fallback-disable false, a requested CodeMode mode becomes Direct; CodeModeOnly remains CodeModeOnly. Therefore, conditional on the verified source/configuration correspondence, the observed fail-closed behavior implies CodeModeOnly was selected through model metadata. This is a strong **inference**, not a direct model metadata observation. Disabling `features.code_mode` cannot by itself force the model to Direct. [Requested and effective tool modes](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/tools/mod.rs#L68-L90). Accessed 2026-09-10.

## Why the direct broker route survives

1. The controller supplies five ordinary dynamic function tools without a custom namespace. DynamicToolHandler creates ordinary function specs and ToolName values with no explicit namespace. The source's default-namespace mapping is `functions`. [Dynamic handler](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/tools/handlers/dynamic.rs#L36-L85). Accessed 2026-09-10.
2. `finalize_tool_router` applies direct-only namespace overrides before registering Code Mode executors. A matching tool with Code Mode availability becomes `DirectModelOnly`. [Override order and transformation](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/tools/spec_plan.rs#L364-L366), [namespace mapping](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/tools/spec_plan.rs#L502-L533). Accessed 2026-09-10.
3. CodeModeOnly hides only tools whose exposure is available in Code Mode. DirectModelOnly tools remain visible as ordinary function specs. Code Mode nested-tool collection excludes these same tools. The direct route is an explicit source-supported control, not a fabricated metadata override. [Visibility rule](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/tools/spec_plan.rs#L770-L783), [nested-tool selection](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/tools/spec_plan.rs#L807-L821). Accessed 2026-09-10.
4. Upstream has a test named `code_mode_only_exposes_default_namespace_tools_directly`. It sets CodeModeOnly plus `direct_only_tool_namespaces=["functions"]`, checks direct visibility/DirectModelOnly, and checks the tool is absent from the Code Mode exec description. This source test was read, **not executed here**. [Exact upstream test](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/tools/spec_plan_tests.rs#L2535-L2551). Accessed 2026-09-10.
5. The unavailable warning is emitted as an event; `maybe_emit_model_warnings_for_turn` does not return an error or terminate the whole turn. The local 026 session deliberately stopped on it. CodeModeService obtains its real provider session lazily; starting its dispatcher does not obtain a host session. Direct router dispatch calls the selected registered handler independently of Code Mode availability. [Warning emission](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/session/turn_context.rs#L1042-L1077), [dispatcher and lazy session](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/tools/code_mode/mod.rs#L200-L248), [direct dispatch](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/tools/router.rs#L348-L382). Accessed 2026-09-10.

**Limit:** Code Mode `exec` and `wait` remain advertised under CodeModeOnly even when the nested set is empty. Their presence is not equivalent to executable JS availability. The disabled provider rejects attempts to create a runtime. A model may nevertheless try this unavailable path and fail. We cannot claim the actual Sol reviewer will use direct tools successfully until the native canary proves that behavior. The synthetic prompt should state the available direct function identities and that Code Mode is unavailable; it should not ask the model to use an unadvertised route or falsify its runtime metadata. [Executor registration](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/core/src/tools/spec_plan.rs#L797-L901). Accessed 2026-09-10.

## Minimal implementation contract

- Preserve all existing model/effort, mounts, scope source pins, auth isolation, empty environment roots, broker allowlist, no-shell/no-web/no-delegation controls, scientific packet manifests, and direct-only namespace configuration.
- Admit at most the **single exact disabled-host fail-closed message** after strict envelope and exact active-thread checks. Require the already validated restrictive profile and source pins as admission context. Reject missing binding, another reason, fallback-to-direct wording, extra text, repeats or any other generic warning. The classifier alone is insufficient because 026 intentionally discarded its reason.
- Exact candidate message for byte comparison: `Code Mode is unavailable because code-mode host is disabled. Code mode will fail closed; enable \`features.code_mode_host\` and install \`codex-code-mode-host\`.`
- Record admission as a narrowly understood unavailable auxiliary executor. Do not call it proof of overall tool readiness, of warning producer identity, or of scientific isolation.
- Require actual direct `read_text` canary success, actual broker refusal on a disallowed read, expected host controls, bounded model accounting and confirmed cleanup before a separate fresh scientific process is allowed. No scientific packet goes to the synthetic process. Unknown later event/warning still stops.
- Preserve a finite fail-fast maximum and exclusive attempt receipt. Request any new combined synthetic-plus-science budget once the complete implementation and offline tests are reviewable. Publication retry must remain separate from model launch.

## Host route, only if direct canary is demonstrably impossible

The process-host route would require enabling `features.code_mode_host`, making a version-pinned `codex-code-mode-host` executable visible, and expanding the reviewed execution boundary. Availability checks only `is_file`, so this would require a model-free real-host smoke test before another model turn; successful file presence would be insufficient. The locator prefers a bundled resource, then a package/sibling executable. The present native mount plan exposes only the Codex binary, so an installed laptop sibling would not automatically appear inside that boundary. [Provider file check](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/code-mode/src/remote_session.rs#L62-L77), [host locator](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/install-context/src/lib.rs#L172-L200). Accessed 2026-09-10.

A preliminary source read supports a pure V8 isolate whose installed globals expose supplied tools and in-memory helpers, with imports rejected rather than filesystem/network module loading. This is **not a completed security audit** of host IPC, resource exhaustion, process inheritance, output serialization or all native callbacks. It does not justify enabling that host now. [V8 context](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/code-mode-runtime/src/runtime/mod.rs#L179-L220), [globals](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/code-mode-runtime/src/runtime/globals.rs#L16-L57), [import rejection](https://github.com/openai/codex/blob/78c290807ce710180111df227df3b7a4fe845452/codex-rs/code-mode-runtime/src/runtime/module_loader.rs#L224-L240). ## Engineering correction

An initial interpretation that this warning necessarily means the reviewer cannot use any tool would be too strong. The source establishes a surviving direct path that was already explicitly configured in 022. The actual failure observed in 026 is the local controller stopping on the warning before testing that path. Readiness remains unverified; admitting every unavailable-host warning or calling the current report a successful reviewer would also be wrong.
