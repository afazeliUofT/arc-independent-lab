# Sol native reasoning-mode audit, 2026-09-09

Engineering consultation only. This is not the independent scientific review. No native client, model, authentication, credential reader, API request, or paid service was launched. Existing repository files were read only; the two newly fetched upstream source files and this note are new delivery artifacts.

## Finding

For the audited Codex 0.151.0 client, explicit `gpt-5.6-sol` with `max` is the highest directly selectable individual reasoning effort in the observed native catalog. `ultra` is a local orchestration selection: it is converted to a non-Ultra backend effort, with a metadata override taking precedence over Max, and independently enables proactive delegation only when the effective runtime is V2. With the programme's V2 delegation disabled, selecting Ultra would not establish extra model reasoning capability. Because the metadata override is not exposed by the retained safe catalog, it would also be incorrect to promise that Ultra always maps to Max.

The exact client cannot explicitly serialize the API field `reasoning.mode=pro` through the audited request path. Its concrete serializable Reasoning structure has only `effort`, `summary`, and `context`, with no `mode` or flattened extra-field map. HTTP and WebSocket requests both use that structure. The native config and app-server schemas likewise expose effort but no reasoning-mode selector. This is a client-route limitation, not a finding that Pro is merely a subscription name or that the account lacks a Pro product elsewhere.

Do not invent `model_reasoning_mode`, `effort=pro`, `serviceTier=pro`, a `gpt-5.6-sol-pro` model ID, custom request headers, a provider override, or paid API access. None is established by this audit. The root investigator is separately checking the current official documentation for API Pro mode and product availability.

## Operational conclusion and limits

The current isolated finite-review implementation can request explicit Max without changing tools, mounts, access, quota protocol or the number of model turns. It cannot truthfully label that request API Pro or claim to have activated Ultra's full delegation capability. Any broader claim that this is the strongest Sol capability available anywhere is unsupported. Whether a newer native client or another subscription surface can expose Pro requires separate evidence and would need re-verification of the enforced boundary before scientific use. No reinstall, upgrade, endpoint substitution or authentication experiment is justified merely by a naming guess.

This audit distinguishes the currently proved native route from the user's objective of the highest usable capability; it does not decide whether that limited route satisfies the user's condition. That choice belongs to the root investigator after integrating current official documentation and the user's exact authorization.
