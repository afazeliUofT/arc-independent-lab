## Question and the distinction that decides it

Can the old boundary estimate in the original construction be recovered with information available to the learner, without an evaluator supplying its privileged coordinate formula? We must distinguish executable fixed model structure, experience-dependent surviving state, and information the evaluator alone sees.

The original learner uses a **supplied, fixed, known feature map**. Its ordinary prediction function can encode either context. The observer previously hardcoded a coordinate difference. A reader that instead obtains two unlabeled feature vectors from that same model and computes its own geometry has not been given an old label, but it still relies on the supplied model and training contract. Removing access to the model's other context feature is a stricter information problem than the original one; it must not be mislabeled the original learner.

We therefore declare three access conditions before observing the follow-up results:

| Access condition | What it can read at recovery | What survives from experience | What this condition can establish |
|---|---|---|---|
| **Own feature API** | Current weights; an unlabeled old-context feature and an unlabeled subsequent-context feature, computed through its own fixed encoder | The same two weights as the original learner; no added experience-dependent state | Accessibility under the original supplied model structure and known update contract, using a newly designed computation |
| **Learned update spans** | Current weights; old and new span bases computed from learner-visible update deltas; the current unlabeled old-query feature | Two weights plus at most two basis vectors in the main cases, totaling four additional floating scalars, with rank/context metadata | Accessibility without querying or supplying the subsequent-context feature geometry, conditional on this extra surviving trace |
| **Erased geometry view** | Current weights and current unlabeled old-query feature only | Two weights; neither basis nor access to the other context's encoder survives/is available | Nonidentifiability over a declared larger class of unknown subsequent-context maps; this does not refute own-feature-API recovery |

The predictor still receives the same training features and responses and makes the same updates. Readers run as instrumented counterfactual computations and never change those updates. The API's context names, zero initialization, fixed linear model, context boundary and A-then-B training contract are supplied structure, not discovered knowledge. The API does not request world responses. Its two feature computations at each recovery are counted separately from training interactions and evaluator probes. The update-span reader never reads those API features except the current old query it must answer.

## Exact reasoning, stated prospectively

Let `a` and `b` denote feature vectors for a unit action in the two contexts. After zero initialization and A-only rank-one SGD updates, `theta_A = a * k`. After B-only rank-one updates, `theta = a * k + b * d`. For noncollinear `a,b`, define `p = a - b * dot(a,b)/dot(b,b)`. Then `dot(p,theta)/dot(p,a) = k`; the old unit-action prediction is `k * dot(a,a)`. This uses generic inner products, not the original coordinate-difference formula. Current API features supply `a,b`, and the known training contract is essential. Arbitrary preceding updates, optimizer momentum in other directions, feature drift or nonzero unaccounted initialization can invalidate it.

The trace reader does not receive `a,b` as setup. It builds orthonormal bases of actual A and B weight deltas using Gram-Schmidt with deterministic sign canonicalization. Normalization removes amplitudes; canonical sign removes the sign of the target from the rank-one basis orientation. It retains no delta magnitude, old gain, response, target, old prediction or boundary weight vector. With disjoint old/new spans, the decomposition of current weights into the two learned spans is unique. Solving for its old component and applying the current old query recovers the boundary prediction. This method cannot uniquely decompose overlapping spans merely from their bases. Ranks and basis entries can still be experience-dependent state; their cost is not zero, and floating-point canonicalization is not a general privacy guarantee.

For the erased geometry view, we construct two allowed training histories with the same final weights and old query but opposite old gains. Put `c = 1-(1-eta)^n`, so the old boundary vectors are `(+c,0)` and `(-c,0)`. Choose the positive root `R` of `R^2-c*R-c^3=0`, put `v=sqrt(R^2-c^2)`, and use subsequent unit features `(-c/R,v/R)` or `(+c/R,v/R)` respectively. Both new gains equal one. After the same finite B schedule, both final states equal `(0,v)` in exact arithmetic. The old query is `(1,0)` in both. A function of those shared inputs alone cannot output both correct boundary predictions. The B API features and learned B span differ, so the richer readers can distinguish the histories. Floating-point residuals will be reported; tiny implementation differences are not a proof of a numerically robust collision and are not used to claim universal impossibility for the original finite codebook.

## Frozen hypotheses and cases

1. **Comparability.** Identity-map runs of all original arm/gain crossings will reproduce the original weights, deltas and ordinary predictions within the declared arithmetic tolerance. Neither original code, config, report nor raw artifacts is changed.
2. **Same-state access.** The own-feature-API reader will recover the A boundary prediction at every B step of the noncollinear original cases. It will also do so under fixed rotations and a reflection, with no geometry or arm ID input to the recovery function. Success is conditional on the supplied rank-one training contract; it is not agent discovery of that contract or spontaneous adoption of the reader.
3. **Extra-state access.** The update-span reader will do the same when its learned bases survive. Frozen B produces an empty new-update span, which this reader can handle. The original model's two-weight state is not silently enlarged in reporting.
4. **Rank failure.** A collinear feature control makes the API projection singular and the two learned spans overlap. These readers should abstain with a stated rank reason. This is a failure of their unique linear decomposition, not an impossibility theorem for every decoder with a supplied finite gain codebook.
5. **Access-boundary failure.** The constructed ambiguous pair will have matching final weights and old query within arithmetic tolerance, distinct required old predictions, and distinguishable API/trace inputs. Its exact derivation establishes nonidentifiability only for the stripped interface across this declared map class.

The config crosses all original old/new gains and shared/orthogonal/frozen arms. Identity, two fixed rotations and one reflection are coordinate stress cases, not independent samples or evidence of broad out-of-distribution discovery. Collinear controls cross the original gains under identity only. The ambiguity pair changes the subsequent feature geometry deliberately; it is not claimed to be another original shared arm. No adaptive cases, hyperparameter tuning, seed expansion or benchmark additions are authorized by this protocol.

## Instrumentation, boundaries and costs

Canonical entry point for this isolated diagnostic: `python3 scripts/run_learner_observer.py --config configs/P2_LEARNER_OBSERVER.json --run-id 20260906_001`. It must refuse execution unless source/config/protocol hashes match the prospective freeze receipt. The root operator separately authorizes execution after the biology pass and alongside generation.

The ordinary predictor has only its weight vector as learned persistent state. The own-feature-API reader allocates transient vectors and arithmetic but adds no experience-dependent survivor. It uses its fixed encoder and supplied phase contract. The span reader starts with an empty old basis, observes only actual A deltas, freezes that basis at the visible boundary, then learns a separate B basis from B deltas. It receives no response or label. These traces survive the same boundary by explicit design; deleting them is a different condition. We make no claim that these bases are free or smaller than storing a boundary estimate in this tiny model.

Pure recovery functions accept only numerical weights/features/bases and a numerical rank tolerance. They do not accept a case ID, arm, map transform, gain, old sample, boundary vector or evaluator loss. Interface inspection and complete traces can detect the stated direct accesses; this is ordinary same-process scientific instrumentation, not an operating-system information-flow boundary or independent reviewer.

The driver stores all current observations, deltas, basis changes, reader inputs and outputs, evaluator-only boundary comparisons, singularity reasons, exact source/config/protocol hashes, original protected-file hashes, environment, version control state, wall-clock limit and completion status. Every run creates a new raw directory; no output is overwritten. Exceptions go to the run's stderr and failure status. The resource cap is sixty seconds internally. There are no model/API calls, network calls, GPU or HPC use. The deterministic construction needs no inference statistics or resource-driven case pruning.

## Interpretation committed in advance

A successful API reader would correct the possible inference that recovery here necessarily depends on knowledge inaccessible to the learner. It would show that a designed generic computation can use already supplied model structure. It would not show that ordinary SGD invents, selects or invokes it, that a new ontology is discovered, or that this access failure dominates current AI. A successful trace reader would establish the analogous conditional accessibility with additional memory. Neither finding automatically promotes the third-ranked broad bottleneck.

A stripped-view ambiguity or collinear-reader abstention would delimit recovery and expose exactly which interface or algebraic assumption matters. It would not undo the original witness that a behavioral failure alone does not prove erasure, and it would not refute an accessible API-based reader. If even the noncollinear API reader fails after implementation checks, the intended same-state claim is not established; report it without changing the original diagnosis in place.

This diagnostic remains separate from generation and contributes no novelty, feasibility or candidate-selection veto. Its report is an append-only follow-up to the approved diagnosis. Shared-workspace collaborators provide consultation, not independent scientific certification.
