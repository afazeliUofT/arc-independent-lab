## Order and scope

Complete the newly required focused biological-constraint pass before generating any candidate. Its question is operational: which constraint changes what a learner can observe, select, change or keep while functioning, and which specifically declared artificial setup removes that constraint? A caveat about what a biological memory assay cannot prove is insufficient. A documented negative is acceptable. Biological results motivate questions; they do not establish engineering efficacy.

The parked-ideas file was first read after Phase 2 opened. It contains only its initialization heading and instructions, with no parked candidate. No population is reconstructed from imagined earlier ideas.

Generate against diagnosis ranks 1, 2 and 3, in that order, one bottleneck at a time. Target 24 short entries per bottleneck, including deliberately extreme or bad ideas. Each entry names an action or learning operation, the diagnosed cause it targets and why it might matter. Draw from biology, the historical pass, orthodoxy violations, inversions and combinations. Do not reject on novelty, feasibility, scalability, plausibility or familiarity. No literature search to disqualify candidates during generation.

Preserve each raw batch as written. Before clustering, write a receipt containing all batch hashes and identifiers. The complete raw text must appear unchanged in `IDEAS.md`, including entries not selected for development. Clustering can reveal duplicates; it must not silently replace their original records.

Only after all generation ends: cluster, choose a diverse set of three to five underlying operations, and specify state, observations, updates, reset behavior, explicitly unchanged components and costs. State what outcome would distinguish addressing the proposed cause from merely improving a score. Cost expressions are descriptions of the specified operations, not measured runtime or a feasibility veto. Only after those specifications, add one-line nearest-method flags. No novelty audit, benchmark selection, experimental gate, efficacy claim or Phase 3 work.

## Human-requested diagnostic follow-up

The learner-computable observer test is a separate, explicitly authorized diagnostic follow-up to Phase 1. It will run alongside ideation, after this preparatory biological pass. Its source, access contract, hypotheses and config must be written before its results exist. Preserve original source and artifacts. Do not turn the diagnostic decoder into a selected candidate by default. A recovery failure bounds its declared information/recovery class; a recovery success does not establish autonomous decoder discovery or a general failure prevalence.

## Accountability

The PI makes the scientific and convergence judgments. Consultations in this workspace have shared tools and files; none is an independently enforced reviewer. No formal result verdict will be issued here. All reported diagnostic numbers require artifact paths and SHA-256 digests. Unknown subscription usage stays unknown; no unattended continuation or additional spending. Publish the approval archive, follow-up evidence, raw population, deliverable and state at the next natural GitHub checkpoint through the established human commit/push route.
