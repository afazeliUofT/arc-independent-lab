# Research evidence returns through GitHub

Effective 2026-09-10, at the funder's explicit request. No attachment handoff is required for reviewer execution evidence. The user executes prepared Git commits and pushes; the PI verifies the resulting public repository tree and reads the actual returned evidence from it.

`delivery/` remains excluded from Git because it also contains private papers, runtime files and temporary material. Never solve evidence publication with `git add -f delivery`, `git add .`, a recursive runtime copy or public paper uploads. The collector copies only its fifteen explicitly named noncredential report, stage, session, authorization, reservation and verdict files. It records original bytes, hashes and missing/refused statuses. It does not open credentials, cached account content, raw client logs or private papers.

The durable entry point is `state/LATEST_REVIEW_030_RETURN.json`. It points to `artifacts/P3_REVIEW_030_RETURN/<evidence-digest>/INDEX.json`, the manifest and exact named file copies. A collector failure uses the separately named `evidence/P3_REVIEW_030_RETURN_FAILURES/` diagnostic path. A collected verdict is an output to verify, not evidence of scientific admission by its existence alone.

Every workflow produces its own explicitly labelled workflow report before collection when the destination is writable. The workflow report can describe an early controller stop or a missing REPORT.json; it is never substituted for a missing execution receipt. Prior launch outcome is immutable. Collection-only invocations may observe later evidence, but never erase the original attempt or infer zero use from missing session files.

An existing main030 directory, kernel prerequisite path or workflow launch reservation means collection only. If none exist, the wrapper may invoke the exact already approved030 controller once under its existing model, scope and ceilings. An exclusive durable marker precedes this invocation. Collection/commit/push retries cannot start another model operation. Keep the original reports, markers and partial files.

The wrapper selects explicit publication paths and verifies exact staged and committed bytes. A pending publication is resumed before any workflow invocation; a Git push retry cannot reach a model-launch branch. No force push, credential change or unrelated staged edit is performed. After the user reports a successful push, the PI fetches GitHub; it does not ask the user to attach the same files.

The user also authorized proceeding with proposed routine work without further approval questions. The030 answer is already published. This handoff introduces no new model identity, paid service, numerical allowance or scientific verdict. Unknown actual030 usage remains unknown until returned receipts establish it.
