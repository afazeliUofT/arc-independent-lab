## Selected path

Complete the primary-method audit and its review before allocating treatment runs to the developed operations. The existing evidence identifies reductions and specification gaps that a larger efficacy experiment cannot resolve. An exact operation can be useful and still fail the programme's novelty criterion. It should become a well-specified comparator or a publishable negative audit, rather than be renamed to preserve a candidate.

C3 is audited unchanged, with its stored historical anchors openly counted. The current-state observer finding receives its own diagnostic status and must not be substituted for C3. The C1/C2/C4 shared proposition remains a separate audit object even if every individual operation is reduced. Its missing interfaces and C4 counterexample are explicit in `evidence/P3_THROUGHLINE_PROPOSITION.md`.

`NOVELTY_AUDIT.md` is the reviewable checkpoint. The final `PROGRAMME.md` will require a reviewed scientific route, the corresponding instrument, tested controls and a measured budget. Filling those sections now with arbitrary run counts or a small available machine would produce a document, not a justified programme.

## What could justify an experiment

| Question remaining after review | Appropriate comparison and instrument | What a result would establish |
|---|---|---|
| Is the observer's surviving estimate accessible under the learner's actual interface? | Preserve the frozen observer evidence and verify its allowed-input contract; if a new case is proposed, distinguish fixed feature-map access, extra trace memory, and access to old targets before designing treatment | Accessibility under a specified contract, not autonomous discovery of the decoder or prevalence in modern systems |
| Does an audited uncertainty-preserving loop change evidence acquisition or reuse? | Exact finite worlds with controlled reachable distinguishing histories; matched model class, action budget and inference substrate; include cases outside that class | A causal diagnosis of an intervention under declared assumptions, even if the intervention is prior art |
| Does an independently identified surviving operation add something beyond the nearest method? | Compare the exact mapped method, matched permitted historical state and computation; select a task that exposes the claimed distinguishing history | The specific surviving claim; a weaker comparator or a renamed implementation cannot establish it |
| Is a retained distinction being recovered, or are stored historical responses being refitted? | For C3-like designs, include direct cached-response refitting with identical information, frozen new encoder and equal refresh access | Whether the claimed access operation has an effect not already explained by replayed response information |

No row is a preapproved experiment. None has been run in Phase 3. If the review finds no novel operation, the appropriate next route is a recorded decision about a bounded return to ideation or a diagnosis-focused publication, not an automatic mechanistic programme. The raw Phase 2 population remains available without claiming that previously undeveloped ideas were refuted.

## Context clearing comes before the treatment implementation

For any later experiment, specify an explicit boundary between transient conversation/process state and the permitted learned channel. The controller must resume in a new process from only that channel and fixed task definitions. A matched negative control receives the same fixed definitions and a cleared learned channel. A positive persistence control receives the intended channel intact. The evaluator holds the answer privately and must not reconstruct model hypotheses, anchor values or action opportunities for one arm only.

World reset is a separate intervention on the environment, with its own declared transition rule. A memory-clearing control that also changes world state would confound the demand. Conversely, preserving raw old trajectories or anchor responses while claiming weights-only retention would invalidate the state restriction.

Before testing any candidate, record exactly which files, process inputs and retained arrays each arm can read, including initial model families, priors, old readouts, query identities and cached activations. Count the construction and evaluation of those objects. A literal equal-parameter comparison is insufficient if one arm receives more history or additional model calls.

## Gate 0 dependencies and compute choice

The capability inventory is a read-only preparation step. It determines the available local client and its advertised command surfaces, and the cluster's visible resource associations. It neither invokes a model nor establishes any security boundary by itself. Read-only reviewer enforcement must be demonstrated separately using synthetic files and attempted writes under the actual configured reviewer runtime. A fresh shared-tools sub-agent is only consultation.

The review packet will pin the approved specifications, audit arguments and relevant source versions. Its reviewer must start without this conversation, operate with enforced read-only access, and return a verdict citing the inspected artifact hashes. The PI's audit conclusions and self-checks cannot substitute for that process. If the available subscription runtime cannot supply it, record the precise missing control; do not claim prompt-level instructions solved isolation.

Authoritative subscription usage remains unavailable to this hosted session. Continue only the user's bounded interactive work; do not create an unattended model loop or infer remaining allowance from time or token estimates. No additional spending or paid API is authorized.

Use the hosted workspace for bounded document work and small deterministic apparatus checks. Use the laptop for its measured local capabilities, while reserving the user-requested cores when the other programme runs. Use Alliance GPU nodes when the selected scientific question needs neural training, large model comparisons or a sweep whose measured cost warrants it. The cluster is a planned resource, not excluded for administrative convenience. Its default-tier access is a provisional assumption until the human-run inventory returns actual association, policy and resource information; a configured maximum is not a guaranteed allocation or queue start time.

Before committing a treatment budget, profile the actual chosen implementation on small, typical and largest planned cases. Count wall time, peak memory, model and encoder evaluations, environment actions, simulator/planner work, persistent bytes and output bytes. Project from the largest observed case. Set the runner's own deadline before any scheduler or hibernation limit, and write a complete final manifest even on an internal timeout. No numerical budget is asserted before those measurements.

For larger outputs, use an explicit staged transfer: finalized chunks and hashes on the execution machine, a durable destination the user can publish without extra spending, then a fresh retrieval and full byte comparison. Test the actual representative output size before the scientific run. GitHub's verified small-document/trace round trips do not establish an untested large-artifact route. If storage, transfer or access cannot sustain the measured output, that run is not ready to start.

## The strongest reasons this route could still be wrong

1. **All decisive structure is supplied.** Fixed transducer classes, atoms, old interfaces and future-loss priors may contain the hardest work. A result within those assumptions can diagnose a failure without solving discovery. An instrument must expose how that structure is built and include misspecified cases; universal correctness conditional on the true world being enumerated is not open-world competence.
2. **Useful information is retained but the programme measures an auxiliary reader the learner never discovers or invokes.** The observer result establishes availability under a narrow API. Autonomous query selection, decoder discovery, computation and invocation remain distinct demands. A later claim about actual competence must inspect the system's actual response path, not only a researcher-designed probe.
3. **The apparent contribution disappears under a properly matched comparator.** The component audit now supplies stronger comparators, and the through-line audit exposes a missing joint guarantee. Check exact reductions and the strongest explicit counterexamples before treatment runs. If the reduction holds, preserve it as the finding instead of weakening the baseline.

These are scientific challenges, not reasons to seek another phase-start approval. The immediate human dependencies are publication of this checkpoint and factual capability reports. A final Phase 3 approval will be requested only when `PROGRAMME.md` is genuinely ready, or a material route change requires it.
