# Checkpoint 032: publication before execution and evidence return

The human's standing instruction authorizes the PI's proposed changes and asks that all needed results return through GitHub. The new handoff records that instruction against the exact 032 scope. Its distributed correction request stays unsigned; the human command derives the pinned `## ANSWER` variant, installs it, and publishes the source and answer before any model operation. This engineering workflow does not supply a scientific review.

A normal invocation has two publications. First it publishes only declared prepared files, including the exact authorization. After that push succeeds and its committed bytes are verified locally, it conditionally calls the finite 032 controller. It then collects the fixed named reports, SESSION/STAGE receipts, attempt and authorization records, workflow records, and any actual verdict; the second publication includes those exact bytes and `state/LATEST_REVIEW_032_RETURN.json`. Missing reports produce a public index. No historical 030 main report is invented or inserted.

A failed push leaves an exact pending publication record and local commit. Every pending retry performs publication only and exits. If the pending phase was setup, the successful retry tells the human to run the same command once more for the remaining conditional operation. If the pending phase was evidence return, the publication completes the handoff. Neither retry can invoke a reviewer. In a normal uninterrupted invocation both phases run from one command.

Any existing 032 attempt directory or exclusive wrapper launch reservation prevents a new controller invocation. A fixed no-argument controller inspection can summarize existing evidence but cannot supply the manual model-launch flag. Existing 030 and 031 files are preserved. The old, already published 030 kernel preflight is a historical reference in the controller; its presence does not count as a 032 attempt and no new kernel probe is scheduled.

The collector reads only its fixed noncredential allowlist with descriptor-relative no-follow walks, regular single-link owner checks, size limits, stable read and final metadata checks. It publishes content-addressed archives without changing source files. Raw client streams are not archived. Its observation is not an atomic snapshot of an active run and does not establish execution admission. Unexpected source types or changes are marked refused, not silently copied. Even workflow import failure yields a fixed publication status rather than fabricating an execution report.

Local validation covers 25 publisher tests, 20 workflow tests and 19 collector tests. The publisher tests include the entire two-phase sequence using an in-memory Git substitute, setup-push failure and retry without a model call, return-push failure and retry without another call, exact scope refusal, and protection against unrelated staged changes. Workflow tests use Python fixture children for interruption and bounded cleanup; collector tests use synthetic files. No real native model, Git commit, or Git push was performed. The release validator additionally reconstructs the exact published base, installs and repeats the approved fixture variant, checks the actual controller's bundle and approval parser, and stages exact Git blobs without committing. Its result is written only after that release validation actually succeeds.

These changes improve publication order and evidence availability. They do not guarantee that the native review will complete, that an emitted verdict will be admitted, or that any scientific candidate survives independent scrutiny.
