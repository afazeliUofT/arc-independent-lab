Date: 2026-09-11. This is PI-owned engineering evidence. No independent reviewer,
native model process, candidate treatment or scientific verdict ran in these tests.

The successor admits exactly R1–R7 plus the supplied CHV79/R1 and PK97/R6 method
comparisons. Overall GO, REVISE_ONCE, KILL and SUSPEND_FOR_DEPENDENCY assess this
analytical review only. The schema explicitly excludes candidate efficacy, global

## Boundary retained and scope replaced

`scripts/p3_focused_review_broker_039.py` reuses the historical
`scripts/p3_review_broker.py` descriptor-relative I/O, no-symlink/no-hardlink
checks, actual whole-file SHA-256 measurement, input-identity checks and disjoint
input/output roots. The historical file was fetched at canonical main commit
`2b28eca52856ebbc18608e8d78f9e24efe269f74`; local bytes match the fetched text
exactly. Its SHA-256 is
`6f2118cb32573c7774db269c09694913040d06adb5eca9e8ca1a0fafe6089536`.
No historical source was edited.

The new dispatch allowlist contains only `read_text`, `read_page_image`,
`hash_file`, `source_access_receipt` and `submit_verdict`. No observer-auditor,
shell, arbitrary execution or source-write operation is advertised or accepted.
The inherited historical observer method is unreachable through this allowlist.
An explicit trusted `synthetic=True` constructor instead admits a singleton
CANARY.txt packet and only read_text; it cannot submit any scientific verdict.

`scripts/p3_focused_review_protocol_039.py` preserves the prior authenticated
thread/turn/request/call identity checks, replay refusal, finite time/call/byte
limits, fixed refusal codes and response construction. Its interface and tool
allowlist now come from the focused broker. Ordinary argument mistakes share an
eight-error ceiling and receive fixed feedback only after actual whole-packet
revalidation. Integrity errors, unknown operations, exceeded limits and protocol
violations remain terminal. Traversal is refused by the original path guard;
its actual exception cause is preserved for the protected canary witness. Refusal
metadata does not log or individually hash the denied path; the protocol retains
whole-request digests, which include request arguments. These are distinct facts.

## Actual source delivery contract

The parent pins BROKER_MANIFEST.json, whose entries define every admissible file.
A manifested FOCUSED_SCOPE.json binds the checkpoint038 scientific manifest,
its complete public input list, the two exact supplied PDF hashes and the trusted
builder's full text, per-page text and PNG derivatives. Derivative provenance is
the parent's responsibility: this broker verifies the admitted bytes, not OCR
accuracy or semantic equivalence of extracted content.

The six governing documents must be delivered completely in their prescribed
order before any other text or paper image. Hash-only calls never count as
reading. The broker merges actually returned text intervals and records measured
image deliveries. A substantive overall verdict requires all 40 public input
texts, each paper's full text (or every per-page text), and these PDF page images:

- CHV79: pages 2, 3 and 4.
- PK97: pages 1, 28, 39, 40, 45, 46, 47 and 48.

The full text requirement provides all methods, results and stated limitations;
the selected images support formula, implemented-method and transfer-boundary
checks. Other page images remain available through the same read-only route.
A supported/refuted source comparison also requires its own PDF digest in its
evidence and actual source delivery. Text evidence must have been delivered
completely. A suspended review may record an unresolved paper dependency without
inventing a paper-reading receipt. Every verdict includes the actual delivery
record and explicitly says that byte delivery is not proof of comprehension or
scientific correctness.

`REVIEW_VERDICT.json` is written once, exclusively to the parent's predetermined
output root, with exclusive creation and stored-byte verification. Its envelope
contains the unchanged reviewer-supplied structured assessment, actual evidence
hashes, source-delivery coverage and the broker's restricted role. It cannot be
overwritten. The surrounding controller must separately establish an independent,
fresh scientific context and actual enforcement of the parent's input/output
boundary. These modules do not establish process isolation by themselves.
