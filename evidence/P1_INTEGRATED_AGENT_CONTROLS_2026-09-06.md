# Integrated agent controls: CLIN and Voyager

Access date for every external source below: **2026-09-06**. Phase 1 consultation; shared tools and filesystem, not an independent review. No model API calls, benchmark executions, paid resources, mechanism proposals, or edits to programme state were made. This audit asks whether interaction-derived state helps after a declared discontinuity, and whether the evidence localizes failures to loss of usable expression of surviving knowledge.

## Judgment

These are positive cases of integrated interaction, persistent records and useful transfer. They narrow a categorical claim that existing AI cannot do the conjunction. They do **not** establish that an acquired, still-valid relation subsequently becomes unusable because of interference. Removing an experiential record from a comparison agent is different from showing that the same record survives in an agent whose performance deteriorated.

The strongest relevant evidence here is a comparison within the same broad agent package, with the experiential channel present or absent. The weakest is an inference from a named memory component, an aggregate task score, or an author's psychological description to a particular internal failure. Neither study is a controlled prevalence estimate for the programme's first-ranked explanation.

## 1. CLIN

**Record and reading extent.** Bodhisattwa Prasad Majumder et al., *CLIN: A Continually Learning Language Agent for Rapid Task Adaptation and Generalization*. The inspected [author-hosted PDF](https://www.cis.upenn.edu/~ccb/publications/clin-continual-learning-from-interactions.pdf) is marked **published at COLM 2024**. Read main text §§1–6 and all appendix methods, prompts, example memories and result tables; reference-list entries were not separately investigated. Download SHA-256: `58eb024519765c0dd73e4a16da7f1db8aeb44e73ef0c345a1666bade445dbb91`. The [project page](https://allenai.github.io/clin/) still supplies the earlier arXiv citation; it was used to locate code, not to override the inspected publication record.

**Primary-paper capsule — methods and decisive observations.** Frozen GPT-4 receives named objects/actions and feedback; an executor maps proposals onto valid actions. Trials reset the environment; summaries persist. Adaptation uses the latest trial and three preceding memories; transfer summarizes best-reward memories from up to ten prior episodes. ScienceWorld new-environment mean reward rises from 48.6 without memory to 52.7 initially with transferred memory; 69.5 includes further adaptation. Task transfer deliberately pairs related tasks sharing objects/locations; ALFWorld uses other tasks of the same type. Appendix C excludes electricity tasks because their nonstandard conventions were judged unfair to LLMs. Replacing constrained memory language with free-form advice lowers ScienceWorld reward by 6.2 points, but changes content as well as wording. Correctness annotations compare initial memories with those from the best later trial, against gold trajectories. The paper acknowledges harmful overly specific memories and absent insights about unobserved activities. These observations support useful, conditional experience transfer, not isolated recovery of an unchanged latent relation. [Full paper, §§3–5, Appendix C and Tables 1, 3–4](https://www.cis.upenn.edu/~ccb/publications/clin-continual-learning-from-interactions.pdf).

**Released implementation, separately scoped.** The [runner at commit `d96c02887f9ee705c1228389cf605f749b86d26d`](https://github.com/allenai/clin/blob/d96c02887f9ee705c1228389cf605f749b86d26d/scienceworld/clin_agent.py) resets action, observation and rationale lists for each trial. It supplies the previous summary to acting and writes raw histories separately. It records oracle paths and permits optional input memories, but the default and README example disable gold-memory input; merely finding that option is not evidence it was used. The runner passes `gold_run=None` to its summarizer. It also stops at a budget derived from oracle-path length and uses three executor retries, whereas the paper describes five. This is therefore implementation evidence, not a verified reconstruction of every published run.

The pinned [prompt and summarization code](https://github.com/allenai/clin/blob/d96c02887f9ee705c1228389cf605f749b86d26d/model_utils.py) limits next-action history to at most five recent records and uses a nominal 2,500-token history cap. The current summary remains a separate input. Memory generation formats prior summaries, not entire earlier raw trajectories, and can discard memories under its token budget. The actor asks for selected learning IDs within its response. This differs in detail from the final paper's separate selection description; exact table-producing configurations remain unverified.

**Diagnostic inference.** The exclusions matter to the scientific target without invalidating the success. A system's ability to transfer within a world family can be genuine even when its original priors make that family unusually accommodating. The relevant distinction is whether the required new relation had to be established from interaction, or whether interaction mainly found instances and conditions under an already useful model of the world. Familiar scientific names alone establish neither answer.

The code also makes a stage distinction concrete. Information can exist in a host array yet be omitted from the model's next decision input. That establishes an architectural access boundary, not that this boundary caused any published failure. Restoring such omitted observations would add decision-time evidence; it would not be a supervision-free recovery test on the same available input. Similarly, a later, better summary generated after fresh trials can reflect new acquisition, corrected interpretation or different selection. Its improvement does not uniquely identify correction of an old readout.

## 2. Voyager

**Record and reading extent.** Guanzhi Wang et al., *Voyager: An Open-Ended Embodied Agent with Large Language Models*. The [journal's own publication list](https://jmlr.org/tmlr/papers/) records **TMLR, March 2024**, with a later ICLR 2025 journal-track certification. The methods version inspected is [author arXiv v2, dated 2023-10-19](https://arxiv.org/html/2305.16291v2); it is an author preprint version of a subsequently published study. Read §§2–4, experimental Appendix B, and the relevant supplied-interface, persistence and retrieval passages in Appendix A. The long primitive-code examples were not all read. Journal PDF access failed; equivalence between the author version and final journal text was not established. Local HTML SHA-256: `99535ed7540b1ddd2db5521bd471cd56dabdd59bc912681de3f85457e59007bc`.

**Primary-paper capsule — methods and decisive observations.** Frozen GPT-4 uses Mineflayer control APIs, named state/inventory, interpreter errors and engineered feedback about missing prerequisites. Successful generated code is retained; descriptions guide retrieval. During exploration death preserves inventory. Transfer instead clears inventory and creates a new world while retaining the skill library; GPT-4 decomposes assigned tasks. Table 2 reports 3/3 successes on each of four tasks with the library, within 50 prompting iterations. The same Voyager package without it succeeds in 2/3 diamond-pickaxe trials and 3/3 trials on each other task, more slowly. AutoGPT also improves when given Voyager's library. These are interaction-derived-record benefits under familiar game semantics and supplied motor competence. They do not isolate unfamiliar-rule discovery. Failures include impossible task proposals, invalid actions and incorrect success judgments. Removing the library changes code availability during generation; it does not test an intact but unreadable acquired relation. Aggregate iteration counts do not hold all inference and execution costs equal. [Author version, §§2–4, Tables 1–2, Appendix B](https://arxiv.org/html/2305.16291v2).

**Released implementation, separately scoped.** Code was pinned and reread at [`55e45a880755d0c8c66ca7fb5fe7962ac8974f89`](https://github.com/MineDojo/Voyager/tree/55e45a880755d0c8c66ca7fb5fe7962ac8974f89). The [orchestrator](https://github.com/MineDojo/Voyager/blob/55e45a880755d0c8c66ca7fb5fe7962ac8974f89/voyager/voyager.py) creates two fresh action messages at rollout reset, then replaces them using the latest code, observations, critique and newly retrieved skills. Saved conversations are not simply restored as the acting history. Learning adds skills after success; inference does not. The executor receives `skill_manager.programs`, which includes the entire stored code library and primitives, although only retrieved skills enter the model prompt.

The [skill manager](https://github.com/MineDojo/Voyager/blob/55e45a880755d0c8c66ca7fb5fe7962ac8974f89/voyager/agents/skill.py) persists code, descriptions and a vector database; matching skill names can replace executable entries. The [README](https://github.com/MineDojo/Voyager/blob/55e45a880755d0c8c66ca7fb5fe7962ac8974f89/README.md) documents loading a library with `resume=False` and a separate checkpoint directory. The [action module](https://github.com/MineDojo/Voyager/blob/55e45a880755d0c8c66ca7fb5fe7962ac8974f89/voyager/agents/action.py) then starts with empty chest memory. Whole-agent resume instead restores chest records. These are different operations; the invocation and server/world setup of each published transfer run were not recovered.

**Diagnostic inference.** A successfully transferred program can encode a conditional procedure rather than an explicit factual world model. That is still knowledge in the programme's operational sense if past experience improves the later decision. Requiring a particular representation would improperly exclude this positive case. Conversely, using a familiar environment and a capable action API makes it inappropriate to credit the result with discovering all of its reusable primitives.

The strong no-library result is particularly informative: the agent package can often construct an adequate procedure during the new task. The stored record contributes useful prior work, but is not always necessary for success at the published allowance. This rules out reading the baseline deficit as a blanket inability to recombine. It leaves open whether larger or more difficult collections eventually cause access or application problems.

Prompt retrieval and executable availability are separate access routes. A function omitted from a prompt can remain callable through another function's dependency. Therefore retrieval rank alone is not a complete state-availability measurement. An audit of failure would have to follow the call chain and the actual generated action before concluding that a relevant skill was unavailable.

## 3. Evidence ordering and implications for the diagnosis

| Question | Strongest usable evidence here | Remaining attribution limit |
|---|---|---|
| Can experience produce persistent, useful records? | Positive transfer with a declared record channel, including a world/inventory reset and a different recipient agent | Prior knowledge and supplied execution competence remain part of the system |
| Can more experience fail to help? | Heterogeneous memory-transfer outcomes and imperfect stored statements | A failed case may involve incorrect content, changed applicability, omitted evidence or faulty execution |
| Is a particular memory format causally responsible? | Within-package ablations change resulting performance | Content, generation, retrieval and computation are not all held fixed |
| Does old useful information survive a loss of ordinary performance? | The implementations expose multiple storage/access boundaries | No matched before/after interference trace here establishes that particular effect |

The first-ranked programme claim should therefore retain its narrow evidential confidence: the small reproduction establishes a witness, while these stronger integrated systems establish useful persistence and transfer. The two facts do not jointly establish that failure of retained-information expression is the dominant cause in integrated agents. That inference would need an acquired relation, its later validity, surviving state and actual failed use connected in the **same** case.

A decisive diagnostic contrast would distinguish three counterfactuals without importing withheld answers: the agent never acquired the needed distinction; it acquired it but its declared surviving channel no longer carries it; or the channel carries it but access/application fails. This is an evidential requirement, not a proposed mechanism or a benchmark implementation. First-trial transfer, subsequent relearning and selection of the best retry must be accounted for separately.

No new paper request is necessary for the claims made here. Final-journal-version equality and exact result-producing configurations remain unverified; neither is silently assumed. No raw published trajectories were reconstructed into an independent result. The two studies suffice for this bounded comparison; recent studies are being examined separately.
